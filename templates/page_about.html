About the AWS Emulator

A local, in-memory emulator of AWS APIs. You keep using the standard AWS SDKs and CLI, point the endpoint URL at it, and get results in milliseconds — no AWS account, no deployment, no cost. Released 11 Nov 2026; source on GitHub (CC0 1.0, vendor/ under Apache 2.0).

Key facts (from the official docs)

FidelityServices are generated from the public AWS API models (the ones behind the SDKs). Valid calls return the same result as AWS; invalid calls return the same errors. Behavior is filled in release by release.
Unsupported callsReturn HTTP 501 NotImplemented. Per-service scores (passing fidelity tests / total) are published on each GitHub release.
StateIn memory only. Stopping or crashing the emulator loses everything. No reset route — just restart it.
IsolationEach started copy has its own port, keys and state. One region and one account (000000000000, user emulator) per copy.
Endpointhttps://127.0.0.1:9297 (HTTPS only, self-signed CA written to ~/.aws/emulator/<port>/ca.pem).
AuthSigV4 on by default using freshly generated keys (EMULATOR… access key). --auth off accepts unsigned requests.
PlatformsNative on Linux (x86_64 / aarch64, glibc 2.17+). Windows & macOS: run it in Docker — this console automates that.
Limits~160 MiB idle, grows with data; cap at 2 GiB. Not for production; no durability/security guarantees. Telemetry is on by default upstream (this console starts it with -t off).
CostNo emulator fee.

How this console works

  1. Install — builds a Docker image from the official Linux RPM.
  2. Run & control — starts/stops the container, reads the generated keys and CA from ~/.aws/emulator/<port>/.
  3. Service pages — 15 services (6 core, 9 generative-AI / ML) with scenario flows and editable single-call forms.
  4. Call monitor (right half) — every call, request and response. Toggle between boto3 hook capture, a wire-level logging proxy, or both.
